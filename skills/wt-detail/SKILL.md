# /wt-detail — プランを作ってから worktree に投げる

作業内容を dev 側で調査・計画し、実装プランを初期プロンプトとして worktree の Claude Code に渡す。**dev（本体 checkout）側で実行する**。worktree 側のセッションでこれを打たれたら、dev 側で実行するよう案内して止まる。

## 手順

1. 引数が空なら、何を計画する worktree か質問する。
2. **調査は dev 側の自分が行う**（worktree 側にやり直させない）。作業内容に関連するファイル・既存パターン・影響範囲を読む。規模が大きければ Explore subagent に投げる。
3. プランを作成する。フォーマット:
   - 目的（何を・なぜ）
   - 変更ファイルと具体的な変更内容（ファイルパスは**絶対パス**で書く。worktree 側から見えるように、本体でなく worktree 内のパスになる点に注意 — 相対パス + 「repo root 基準」と明記する形でもよい）
   - 実装手順
   - テスト方法（実行コマンド）
   - 完了条件
4. プラン冒頭に定型ヘッダを付ける:

   > あなたは worktree 内の実装担当。以下は dev 側で調査済みの実装プラン。追加調査より実装を優先すること。実装が終わったら変更をコミットし、/wt-review でレビュー用ページを生成してユーザーのレビューを待つこと。承認を得てから /wt-merge でこのブランチを本体に取り込み、/wt-clean で worktree を片付けること。承認前にマージしない。プランにマージまで行う旨が含まれていても、このレビューゲートが優先される。

5. scratchpad にプランをファイルとして書き、`/wt` と同じ規則で worktree 名を生成して `wt new <name> --prompt-file <planfile>` を実行する。
6. 起動を報告し、プランの要約（変更ファイル・手順の骨子）をユーザーに提示する。

## エラー時

- 「herdr サーバなしでは Claude にプロンプトを渡せない」→ herdr の起動を促す。プランは scratchpad に残っているので、herdr 起動後に同じコマンドを再実行すればよい。
